## 继续优化：日志阻塞与持续压测

用户要求继续完成剩余应用层工作；不新增集群平台或默认后台业务系统。

- 用受控慢输出复现旧实现问题：一次 150 毫秒的日志输出会卡住事件循环，同期协程无法前进。
- 改为每进程一个后台日志写入线程；发送端先冻结请求 ID、完成脱敏和 JSON 序列化。默认最多缓存 1000 条，每条最多 16 KiB；满队列、超大记录和关闭后的新记录会丢弃并计数。数据库审计不经过该队列。
- 配置集中于 `app/core/config.py` 和 `.env.example`：`LOG_QUEUE_CAPACITY` 默认 1000、最多 10000；`LOG_SHUTDOWN_TIMEOUT_SECONDS` 默认 2 秒、范围 0～30 秒。有限等待仅约束应用日志收尾；已进入操作系统的阻塞输出不能由 Python 安全中断。
- 确定性专项测试覆盖：输出持续阻塞、20 个 HTTP 请求仍完成、队列满、请求上下文和可变字段快照、脱敏、写入/刷新/短写失败、启动失败、超时和取消关闭、正常排空、初始化失败资源清理。
- 压测增加 `--duration`（大于 0、最多 3600 秒，与 `--requests` 互斥）；到时停止新增请求，已有请求受整体超时约束。延迟样本超过 10000 时采用均匀抽样，并明确标记估计分位数；另报成功吞吐。
- 双实例集成测试同时覆盖固定 100 次与持续 2 秒模式，读取真实受保护接口、每进程 PostgreSQL 连接池仅 1 条；这是工具/小池正确性证据，不是生产持续负载验收。文档另说明预热、并发阶梯、持续测试和资源观察方法。
- 最新全量隔离验证：**867 passed，0 failed，0 skipped，62.69 秒**；24 条依赖警告来自 Alembic 旧配置约定和故意用错误算法的 JWT 负例。
- 独立代码复核与日志/压测工具测试通过；Ruff、严格类型检查、Skill/209 文件发布包校验、wheel 构建和独立导入通过。

## 数据库网络超时补齐

用户同意优先修复这一应用层问题并准备发布。范围：客户端命令/连接预检超时，超时及取消后清理坏连接，安全 `503`，不重放业务写入，故障恢复测试、文档及安装同步。集群部署和生产容量测试仍按实际项目需要处理。

- 实现完成：`DATABASE_COMMAND_TIMEOUT_SECONDS` 默认 20 秒，每条驱动命令和完整连接预检有客户端时限；服务端 SQL/锁超时保留。多条 SQL 的整个 HTTP 请求仍需按业务设定总时限。
- 使用有界 `SELECT 1` 预检替代内置 `pool_pre_ping`；确认断线时最多替换一次连接，连续预检失败也返回安全 `503`，不将程序错误统一归成数据库故障。
- 客户端超时只淘汰当前连接，物理连接退休直接终止本地连接，避免取消/回滚/关闭继续等网络；正常归还连接仍执行原事务重置，外部取消原样传播。
- 验证使用新建隔离 PostgreSQL/Redis 和仅监听回环地址的 TCP 故障代理。覆盖查询、提交、回滚、checkout 的静默丢包，取消中的查询/预检，空闲断线重连，停机释放，健康连接保留，以及连续预检断线的重连上限与恢复。没有操作真实业务库。
- 专门验证数据库已提交但回包丢失时，接口返回 `503`、数据库恰好写入一次；超时不等于回滚，业务必须核实结果，代码不自动重放写入。
- 最新全量：883 passed，0 failed，0 skipped，62.36 秒；24 条既有依赖警告。最后类型与预检异常分类补强后另跑 12 项数据库网络边界回归，不叠加统计。
- Ruff、严格 mypy、Skill 与发布内容校验、wheel 构建/独立导入验证完成。变更留在 Unreleased，本轮未升版或发布 GitHub；正式发布时仍需更新版本元数据并检查 CI。

## 默认单机，集群按需

限流共用该 Redis，只填 `DATABASE_URL`、`REDIS_URL`，不额外询问必须选择哪种
集群。已有项目保留现有拓扑；只有明确需要时才启用 Sentinel、Cluster、读写分离
或独立限流 Redis，集群建设与维护仍由运维负责。

地址改为注释，本地 Compose 的第二个 Redis 改为显式 profile 才启动。已有客户端
运行逻辑无需改动；共用 Redis 的默认回退已实现，按需能力保留。
