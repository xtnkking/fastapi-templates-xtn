# Optional Country Catalog

Read this reference only when the product explicitly needs a country or region
table, a country selector, international calling-code display or filtering,
address-country storage, or a maintained country directory. The ordinary RBAC,
user, proxy, locale, currency, and time-zone baselines do not require this table.
Treat it only as an opt-in extension inside a project already using this Skill;
do not select or load this Skill solely for a generic country table task.

Search terms: `country table`, `countries`, `country selector`, `country_code`,
`calling_code`, `name_zh`, `name_en`, `flag_url`, `ISO 3166`, `国家表`, `国家区号`.

For concrete SQLAlchemy, Alembic, query, route, import, and test shapes, read
[Country catalog PostgreSQL](country-catalog-postgresql.md) after this contract.

## Product Boundary

This module is optional and is not part of the copied PostgreSQL RBAC asset.
Do not create its table, routes, seed job, Redis keys, or frontend controls unless
the current product needs them. A transient country string returned by an IP
geolocation provider does not by itself justify a maintained catalog.

Preserve an existing project's established country model. For a greenfield
catalog, resolve only the one product decision that cannot be inferred: the
approved code set. Determine whether the product supports all entries from a
named, versioned ISO 3166-1 alpha-2 source or an explicit business subset. Do not
silently call an incomplete subset "all countries". Record the source, version or
retrieval date, approved subset rule, and redistribution license before seeding.

The baseline below otherwise makes the decisions for the implementer. It models
countries and dependent territories together because alpha-2 catalogs commonly
contain both. Use `country` in stable API and database names when the product
already does so, but label the UI `国家/地区` when that is more accurate.

## Fixed Table Contract

Use `countries` for a new table. Do not add a synthetic integer or random ID:
the uppercase two-character `country_code` is the stable, non-sequential natural
primary key and public identifier. A standards-backed natural key is compatible
with this Skill's anti-enumeration rule; authorization and object policy still
apply wherever country maintenance is privileged.

| Column | PostgreSQL shape | Contract |
| --- | --- | --- |
| `country_code` | `varchar(2)` primary key | Uppercase ASCII alpha-2 code; never use a display name as a key. |
| `calling_code` | `varchar(3)` | Digits only, without `+` or a leading zero; format `+` only for display. It is not unique. |
| `name_zh` | `varchar(128)` | Required Chinese display name; preserve Unicode text and do not use it as identity. |
| `name_en` | `varchar(128)` | Required English display name; do not assume current values are legal ISO short names. |
| `flag_url` | `varchar(2048)` nullable | Optional HTTPS presentation asset; never a trusted country identifier. |
| `is_active` | `boolean` | Whether the entry can be selected for new business data; default `true`. |
| `version` | `bigint` | Non-negative optimistic-concurrency value for optional runtime maintenance; default `0`. It is not an ID. |
| `created_at` | `timestamptz` | Generated by PostgreSQL when the row is inserted. |
| `updated_at` | `timestamptz` | Generated or explicitly updated by the authoritative write transaction. |
| `deleted_at` | `timestamptz` nullable | Soft-delete tombstone. A deleted row must also be inactive. |

Do not copy integer `status`, Unix-second `create_dt`, or Unix-second `update_dt`
columns from an example administration screen. PostgreSQL owns typed timestamps,
and a boolean expresses this baseline's selectable state without an unexplained
numeric enum. If the existing product has a documented multi-state lifecycle,
preserve it and still retain `deleted_at` for removal.

`calling_code` is a string even if a CSV reader infers numbers. Several countries
or territories share `1`, `7`, `39`, `44`, `61`, and other calling codes, so do
not add a unique constraint. The value is a country calling-code hint, not a full
phone-number parser or proof that a number belongs to that country. Products that
need multiple complete dialing prefixes per country should add a child table and
use a maintained phone-number library rather than overloading this column.

Display names can repeat or change and therefore are not unique. Store them in
Unicode without compatibility normalization that changes presentation. For more
than Chinese and English, replace fixed name columns with a deliberate translation
table; do not add one preemptively.

## Lifecycle And References

These states are distinct:

- Live and active: available for new selections and ordinary list results.
- Live and inactive: not selectable for new data, but retained for existing
  references and possible re-enable.
- Soft-deleted: hidden from ordinary list and detail responses and never selected
  for new data. Restore is an explicit action and never an import side effect.

Every ordinary runtime removal sets `is_active=false` and `deleted_at` in one
transaction. Do not expose or implement a hard-delete route. A physical delete is
limited to an explicit reviewed migration, disposable test teardown, or another
separately approved maintenance exception. Existing business rows keep their
country code; use a foreign key with restrictive physical-delete behavior rather
than cascading country removal into orders, users, addresses, or reports.

When validating a new or changed business row, reject inactive or deleted country
codes. Historical reads may still join the stored country so old records remain
understandable. Do not erase a country code from historical rows merely because
the catalog entry becomes inactive.

## Source CSV Contract

For the five-column source shape used by this Skill, require this exact header:

```text
country_code,calling_code,name_zh,name_en,flag_url
```

Accept UTF-8 with or without a BOM. Treat every column as text during staging.
`flag_url` cells may be empty; all other cells are required. Before any database
write, verify:

- exact header and row width;
- at least one data row and the validator's one-MiB/1,000-row safety limits;
- no malformed UTF-8, control or Unicode formatting characters,
  leading/trailing whitespace, or empty required values;
- unique `country_code` values matching `^[A-Z]{2}$`;
- `calling_code` values matching `^[1-9][0-9]{0,2}$`, without requiring uniqueness;
- bounded display-name lengths without treating names as keys;
- optional flag URLs are absolute HTTPS URLs on the default port, have no
  embedded credentials, query, or fragment;
- when any `flag_url` is non-empty, a formal import-ready validation explicitly
  supplies at least one product-approved flag-host allowlist entry, and every
  allowlist entry and URL host uses valid ASCII DNS hostname syntax;
- the exact code set equals the approved, versioned coverage manifest.

Run the supplied read-only validator before adapting an import:

```powershell
python -B scripts/validate_country_csv.py countries.csv `
  --expected-codes-file approved-country-codes.txt `
  --allowed-flag-host flagcdn.com
```

The validator deliberately does not embed an ISO list or download one at runtime.
It requires `--expected-codes-file` for an import-ready result. Use the mutually
exclusive `--structure-only` mode only for an explicitly non-authoritative
inspection. `--structure-only` is never import approval: it reports
`membership_checked=false`, and that result must not reach a database import.
Use `--expected-count` and repeated `--required-code` only as additional
assertions, not as a substitute for exact-set comparison.

Formal import with any non-empty `flag_url` requires one or more explicit
`--allowed-flag-host` values. The validator compares normalized hosts exactly;
it does not infer trust from a parent domain or accept wildcard entries. Supply
only approved ASCII DNS hostnames. Unicode display spellings, trailing-dot names,
and other non-DNS host syntax are invalid. A structure-only run without a host
allowlist may report this as a warning only because that mode cannot approve an
import.

Do not put a source data file into a public Skill merely because it is available
locally. Confirm its provenance, redistribution permission, update policy, and any
flag-provider terms first. When those facts are absent, publish the schema,
validator, and import contract but leave the dataset out of the repository.

## Import And Atomicity

Country import is ordinary configuration data, not an RBAC control-plane write.
It does not acquire `rbac_state`. It still requires one PostgreSQL transaction:

1. Parse and fully validate the file before mutating durable rows.
2. Acquire a transaction-scoped advisory lock dedicated to country import so two
   operators cannot update the catalog concurrently.
3. Load validated values into a temporary or in-memory staging set and check for
   incoming codes that collide with soft-deleted rows.
4. Insert new rows and update changed live rows by `country_code`. Increment
   `version` only when stored business fields actually change.
5. Never reactivate a disabled row, restore a deleted row, or delete/disable a row
   merely because it is absent from an import file.
6. Commit the complete import or roll it all back. Do not seed at application
   startup, call an external country service inside the transaction, or hide a
   partial import behind retries.

If a separately reviewed operation treats an approved file as a complete
authoritative snapshot, calculate removals explicitly, show the operator the
planned changes, and soft-delete only after that separate confirmation. The
ordinary upsert path never interprets absence as deletion.

For reproducibility, record the approved source identifier, source version or
retrieval date, file hash, row count, actor or deployment identity, and result in
deployment evidence. Do not add these values to every country row unless the
product needs row-level provenance.

## API Contract

Do not add an API if countries are used only by server-side validation or a build
artifact. When a frontend needs the directory, the baseline exposes only:

- `GET /api/v1/countries` for live, active rows with optional `q` and
  `calling_code` filters plus `page`, `page_size`, and deterministic
  `country_code` ordering;
- `GET /api/v1/countries/{country_code}` for one live, active row, normalizing the
  path value to uppercase and returning the standard concealed `404001` when the
  row is missing, inactive, or deleted.

Use the four-field response envelope and page data from
[API response standard](api-response-standard.md). Return the canonical stored
`calling_code` without `+`; the frontend may render `+{calling_code}`. Return
`flag_url` as nullable and provide a text fallback. List and detail reads do not
need Redis because this catalog is small and database-backed; normal HTTP caching
may be added only when the existing product already owns its invalidation policy.

Country lookup is optional business data and both read routes require login by
default, even for a registration page. A page that must show countries before
login needs an explicitly approved exception designed by that product, not an
implicit anonymous API from this Skill. Apply the per-operation authenticated
read policy and never return deleted rows.

Do not expose create, update, enable, disable, delete, restore, or import routes by
default. Prefer reviewed migrations or an operator command. If runtime management
is a real product requirement, use neutral `GET`/`POST` resource routes, explicit
`countries:read` and `countries:manage` capabilities, strict request models,
`expected_version`, the soft-delete lifecycle above, and the same hierarchy checks
as other privileged operations. Record these configuration changes in the
business audit module, not `rbac_audit_events`.

## Flag Safety

A flag URL is presentation metadata. Never infer a country from it, use it for
authorization, or fetch arbitrary submitted URLs from the backend. Prefer a local
licensed asset set or a deterministic URL derived from validated `country_code`.
When an external CDN is used, approve its license and availability policy, enforce
HTTPS and an explicit approved ASCII DNS hostname allowlist at ingestion, apply
an appropriate browser CSP, include accessible text, and render a fallback when
the asset fails. Do not make country lookup fail because a flag provider is
unavailable.

## Verification

When this optional module is implemented, prove:

- the migration creates no sequence, identity, or synthetic numeric country ID;
- all checks, timestamp types, partial live indexes, and the deleted-implies-
  inactive constraint exist in PostgreSQL;
- the source is strict UTF-8, has the exact header, matches the approved code set,
  and treats shared calling codes as valid;
- import is atomic, idempotent for unchanged rows, increments versions only for
  real changes, and cannot silently restore tombstones or remove absent codes;
- ordinary list/detail reads return only active non-deleted rows, use stable
  ordering and the standard response envelope, and do not fetch flag URLs;
- inactive and deleted entries cannot be selected for new business writes, while
  historical foreign-key references remain intact;
- every runtime removal is a soft delete and no HTTP hard-delete path exists;
- optional management routes enforce capability, hierarchy, version, transaction,
  and business-audit requirements; and
- no country table, import, or API appears when the product did not request this
  module.
